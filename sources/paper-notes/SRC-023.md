# 这篇到底研究什么

这篇尝试在桨上装小传感器，看桨何时在水里。作者先做水深和温度校准，再同步记录桨信号、艇加速度与肘部衣物传感器。结果能帮助分辨左右划程及入水时间。传感器没有成功直接测出划桨力。

# 实际做了什么

- 实验/实测：Flexiforce改装封装、水深/温度校准与水上试用；蓝牙同步桨、三轴加速度和肘部应变（PDF p.2–3）。
- 数值模拟/理论模型：无水动力模拟；压力按静水校准作水深代理。
- 综述：无。

# 真正测量或计算的变量

- 桨尖传感器读数/校准水深、温度；入水/拉桨持续时间、左右差别；艇三轴加速度、衣物肘部应变。
- 不将压力代理读数列为成功测得的桨推进力。

# 最重要的 3～8 个发现

1. 浅水校准时各传感器响应不同，封装也影响响应，需要筛选/校准。定位：PDF p.3，§3.1、图3。
2. 静水压力占主导，入水角度和其他贡献未分离，不能跨左右桨、试次或划手直接比较压力幅值。定位：PDF p.4，§3.2。
3. 入水时间可与其他信号同步分析左右划程，但作者结论明确未直接测出stroke force。定位：PDF p.4–5，图4–5、§4。

# 对 Packraft 有什么用

- 可直接参考：传感器测到什么、没测到什么的校准记录方式。
- 只能做机制类比：用入水时刻同步动作与艇运动。
- 暂时不能迁移：压力信号换成packraft划桨力或最佳支撑。

# 最容易误用的地方

- 静水/竞速硬壳 → 白水充气艇未验证。
- 高速机动艇不适用；复杂天然河流的动压和夹气未校准。
- 一个桨尖点的压力不是全桨叶积分合力。

# 值得以后学习的概念

- 代理信号：传感器数值代表某现象，不能默认代表所有力。
- 同步：把不同传感器的同一时刻对齐。
